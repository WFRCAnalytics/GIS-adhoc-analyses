Center Buildout Capacity

Daybreak, Saratoga Springs Downtown, and The Point

Purpose

Estimate additional housing units and jobs at full buildout for three WCV centers:

  • Daybreak and Saratoga Springs Downtown: from REMM-forecast post-2025 development, applying each center’s median dwelling-unit-per-acre and employment-density (FAR + job-space) assumptions to the forecast residential / commercial-employment development mix.
  • The Point: from the development schedule the Point team has provided directly, rather than from REMM.

Spatial joins, filtering, and aggregation below run in geopandas/pandas. The base-year parcels come from remm_base_year_data.gdb, which is cached as GeoParquet on first run (see below) so later runs just read that instead of re-parsing the FileGDB.

REMM parcels: load and cache as parquet

Show the code 
from pathlib import Path

import geopandas as gpd
import pandas as pd

paths = {
    "raw": Path("_data/raw"),
    "processed": Path("_data/processed"),
}
paths["processed"].mkdir(parents=True, exist_ok=True)

paths.update({
    "gdb": paths["raw"] / "remm" / "remm_base_year_data.gdb",
    "buildings_2055_pkl": paths["raw"] / "remm" / "run1842year2055allbuildings.pkl",
    "parcels_geoparquet": paths["processed"] / "parcels_2023.parquet",
    "centers_geoparquet": paths["processed"] / "centers.parquet",
    "buildings_2055_parquet": paths["processed"] / "buildings_2055.parquet",
})

# one-time read of the two vector sources, cached as GeoParquet so later runs
# don't re-parse the FileGDB or re-fetch the REST layer.
if not paths["parcels_geoparquet"].exists():
    parcels_gdf = gpd.read_file(paths["gdb"], layer="parcels", columns=["parcel_id", "parcel_acres"])
    parcels_gdf.to_parquet(paths["parcels_geoparquet"])

if not paths["centers_geoparquet"].exists():
    centers_gdf = gpd.read_file(L["center_boundaries"], columns=["CenterName", "CenterType"])
    centers_gdf.to_parquet(paths["centers_geoparquet"])

if not paths["buildings_2055_parquet"].exists():
    buildings_full = pd.read_pickle(paths["buildings_2055_pkl"]).reset_index()
    # 'note' mixes strings with an int 0 sentinel (no dedicated null), which pyarrow
    # can't write as a single column type -- cast to string so every row survives
    # as-is (0 -> "0") rather than dropping columns to sidestep the type error.
    buildings_full["note"] = buildings_full["note"].astype(str)
    buildings_full.to_parquet(paths["buildings_2055_parquet"])

parcels = gpd.read_parquet(paths["parcels_geoparquet"])
centers = gpd.read_parquet(paths["centers_geoparquet"]).to_crs(parcels.crs)

Parcels within each center

Centroid-in-polygon join (not a straight intersection) so a parcel straddling a center boundary is assigned to exactly one center, not double-counted.

Show the code 
parcel_centroids = parcels.set_geometry(parcels.geometry.centroid)

parcels_in_centers = gpd.sjoin(
    parcel_centroids, centers[["CenterName", "geometry"]], predicate="within", how="inner"
)[["parcel_id", "parcel_acres", "CenterName"]]

parcels_in_centers.groupby("CenterName").agg(
    n_parcels=("parcel_id", "count"), total_acres=("parcel_acres", "sum")
)

Daybreak & Saratoga Springs: REMM developable land

Follows the original pseudocode directly: filter the 2055 buildings table (run1842year2055allbuildings.pkl, one row per building) to parcels within our two centers, keep buildings with year_built > 2025, take the unique parcel ids from that, then sum parcel_acres for those parcels.

An earlier version of this shortcut off the parcel-level parcel_progression_metrics table instead, since it already carries a single year_built per parcel. That’s only valid if every building on a parcel always shares the same year/type – checked directly: 162 parcels regionwide have more than one building, 2 of them are in our two centers, and in both cases the buildings on that parcel happened to share the same year_built. That was a coincidence of this dataset, not something the data guarantees in general, so this now filters at the building level as originally specified rather than relying on it holding elsewhere.

Show the code 
buildings_2055 = pd.read_parquet(
    paths["buildings_2055_parquet"],
    columns=["parcel_id", "year_built", "general_type", "residential_units", "job_spaces"],
)

our_parcels = parcels_in_centers[
    parcels_in_centers["CenterName"].isin(["Daybreak", "Saratoga Springs Downtown", "The Point"])
]
buildings_in_centers = buildings_2055.merge(
    our_parcels[["parcel_id", "CenterName"]], on="parcel_id"
)

post_2025_parcel_ids = buildings_in_centers.loc[
    buildings_in_centers["year_built"] > 2025, "parcel_id"
].unique()

developable_land = (
    our_parcels[our_parcels["parcel_id"].isin(post_2025_parcel_ids)]
    .groupby("CenterName")
    .agg(n_parcels=("parcel_id", "count"), total_acres=("parcel_acres", "sum"))
    .reset_index()
)

Forecast development mix and buildout capacity

Show the code 
# residential vs. commercial/employment forecast ratio (2050 or 2055) from
# buildings_in_centers (year_built > 2025): sum residential_units and
# job_spaces (or building_sqft by general_type) rather than trying to label
# a whole parcel's acreage as "residential" or "nonres" -- some parcels mix both.
# apply center's median DwellingPerAcre to residential share of acreage -> housing units
# apply center's median employment density (NonResFAR + job-space assumption) to
# commercial/employment share of acreage -> jobs
