Purpose

How many vehicle miles of travel (VMT) does UTA transit service run in a calendar year, and how does that split across Local Bus, Express Bus, Bus Rapid, Light Rail, Streetcar, Flex, Commuter Rail, and Ski Bus?

This analysis answers that for 2026 from the actual published schedules, not an annualization of one sample week. GTFS feeds change several times a year (service changes, detours, holiday schedules), so every service date is assigned to the feed snapshot that was in effect that day, and the miles of every scheduled trip are added up.

NoteWhat “VMT” means here

Scheduled in-service (revenue) vehicle miles: the distance of each trip scheduled in GTFS, from its first to its last stop. It does not include deadhead (garage pull-out/pull-in and repositioning), nor actual operations (missed trips, detours, extra service). Expect it to run somewhat below UTA’s reported NTD vehicle revenue miles plus deadhead.

It covers fixed-schedule service only, whatever UTA publishes as scheduled trips in GTFS. On-demand service (UTA On Demand microtransit) is not included: none appears in any of the 2026 feeds. UTA’s scheduled Flex routes (the F-prefixed route-deviation routes) are in GTFS with fixed trips, so they are counted, reported as their own Flex mode.

Data Sources

Data Source Notes
UTA GTFS snapshots Mobility Database feed mdb-170 (Utah Transit Authority) Every archived snapshot of the feed; those covering 2026 are cached under _data/remote/gtfs/
Route -> mode route_short_name lookup supplied by the analyst (below) Falls back to GTFS route_type for rail if a name is missing

Authentication uses MOBILITY_DATABASE_REFRESH_TOKEN from .env (see .env.example). Downloads are cached; delete a file under _data/remote/ to re-fetch it.

Route-to-mode lookup

Modes follow the analyst-supplied UTA lookup by route_short_name. Core route 35M (COR in the lookup) is folded into Local Bus; The S-Line streetcar (route 720) is reported as its own Streetcar mode, not Light Rail. Flex routes (the F-prefixed route-deviation routes, e.g. F11 and F94) are split out of Local Bus into their own Flex mode. Microtransit (on-demand) has its own category in the lookup, but no such routes exist in the feeds, so it reports zero. Four routes were added to Bus Rapid (BRT): OGX and UVX (the supplied lookup’s comment names them as the BRT routes but they were missing from its list), and 50X and MVX (the Midvalley Express, UTA’s third BRT line, which opened April 12, 2026 and is published under both names). CS1, CS2 and CS3 are UTA’s seasonal canyon ski buses (to Alta, Snowbird and Brighton), neither local nor express, so they are reported separately as Ski Bus. Any other route not in the lookup is reported as Unmapped rather than guessed (except rail: GTFS route_type 0 is Light Rail, 2 is Commuter Rail).

Which feed was in effect each day

The Mobility Database archives each UTA feed as it is republished (about 75 snapshots, many identical). For every date in 2026 we take the latest snapshot published on or before that date whose service period covers it. If none was published yet (the very first days of a schedule), the earliest snapshot covering it is used.

Trip miles, step by step

Each step below works on all snapshots at once, keyed by snapshot id.

Step 1: read the GTFS tables

Only the columns needed are kept. From stop_times.txt (the biggest file) we keep just each trip’s first-to-last shape_dist_traveled span.

Show the code 
routes, trips, shapes, span, cal, cdates = {}, {}, {}, {}, {}, {}
for sid in snapshots:
    with zipfile.ZipFile(zips[sid]) as zf:
        assert "frequencies.txt" not in zf.namelist(), f"{sid}: frequency-based trips not handled"
        routes[sid] = pd.read_csv(zf.open("routes.txt"), dtype=str)
        trips[sid] = pd.read_csv(zf.open("trips.txt"), dtype=str)
        shapes[sid] = pd.read_csv(zf.open("shapes.txt"), dtype={"shape_id": str})
        cal[sid] = pd.read_csv(zf.open("calendar.txt"), dtype={"service_id": str})
        cdates[sid] = pd.read_csv(zf.open("calendar_dates.txt"), dtype={"service_id": str})
        stop_times = pd.read_csv(zf.open("stop_times.txt"),
                                 usecols=["trip_id", "shape_dist_traveled"],
                                 dtype={"trip_id": str}, skipinitialspace=True)
    sdt = (stop_times.dropna(subset=["shape_dist_traveled"]).groupby("trip_id")
           .shape_dist_traveled.agg(["min", "max"]))
    span[sid] = (sdt["max"] - sdt["min"]).rename("span")

print(f"{len(snapshots)} snapshots loaded; latest has {len(trips[snapshots[-1]]):,} trips.")

Step 2: length of each shape

Haversine distance (miles) between consecutive shape points, summed per shape_id. shape_dist_traveled is in kilometers in UTA’s feed, so lengths come from coordinates rather than that column’s units.

Show the code 
shape_len = {}
for sid in snapshots:
    s = shapes[sid].sort_values(["shape_id", "shape_pt_sequence"]).reset_index(drop=True)
    lat, lon = np.radians(s.shape_pt_lat.to_numpy()), np.radians(s.shape_pt_lon.to_numpy())
    a = (np.sin(np.diff(lat) / 2) ** 2
         + np.cos(lat[:-1]) * np.cos(lat[1:]) * np.sin(np.diff(lon) / 2) ** 2)
    seg = 2 * 3958.8 * np.arcsin(np.sqrt(a))  # Earth radius in miles
    same_shape = s.shape_id.to_numpy()[1:] == s.shape_id.to_numpy()[:-1]
    s["seg"] = np.r_[0.0, np.where(same_shape, seg, 0.0)]
    shape_len[sid] = s.groupby("shape_id").agg(
        shape_miles=("seg", "sum"), shape_sdt=("shape_dist_traveled", "max"))

Step 3: miles of each trip

A trip may cover only part of its shape (short-turns). The fraction (last stop - first stop) / full shape of shape_dist_traveled trims the shape length to what the trip actually serves; trips without stop distances use the full shape.

Show the code 
trip_miles = {}
for sid in snapshots:
    t = (trips[sid]
         .merge(shape_len[sid], left_on="shape_id", right_index=True, how="left")
         .merge(span[sid], left_on="trip_id", right_index=True, how="left"))
    frac = (t.span / t.shape_sdt).where(t.shape_sdt > 0).clip(upper=1.0).fillna(1.0)
    t["miles"] = (t.shape_miles * frac).fillna(0.0)
    if t.shape_miles.isna().any():
        print(sid, f"-> {int(t.shape_miles.isna().sum())} trips without a shape (0 miles)")
    trip_miles[sid] = t

Step 4: trips and miles by service and route

Add up trips by service_id x route_id, so each date only has to pick its active services. Some snapshots have trips whose route_id is missing from routes.txt (a feed defect); those routes’ names and types are recovered from the same route_id in other snapshots.

Show the code 
# route_id -> name/type across all snapshots, to recover routes missing from routes.txt
route_lookup = (pd.concat([r[["route_id", "route_short_name", "route_type"]]
                           for r in routes.values()])
                .drop_duplicates("route_id", keep="last").set_index("route_id"))

service_route = {}
for sid in snapshots:
    sr = (trip_miles[sid].groupby(["service_id", "route_id"])
          .agg(trips=("trip_id", "size"), miles=("miles", "sum")).reset_index()
          .merge(routes[sid][["route_id", "route_short_name", "route_type"]],
                 on="route_id", how="left"))
    orphan = sr.route_short_name.isna()
    if orphan.any():
        sr.loc[orphan, ["route_short_name", "route_type"]] = (
            route_lookup.reindex(sr.loc[orphan, "route_id"]).to_numpy())
        print(sid, "-> routes missing from routes.txt, recovered:",
              sorted(sr.loc[orphan, "route_short_name"].unique()))
    sr["route_type"] = sr.route_type.astype(int)
    service_route[sid] = sr

Step 5: miles for each date

For each date, find the services running that day (calendar.txt weekday pattern, plus or minus the calendar_dates.txt exceptions) in its assigned snapshot and add up their routes.

Show the code 
frames = []
for d, sid in assigned.items():
    key, weekday = int(d.strftime("%Y%m%d")), d.strftime("%A").lower()
    c = cal[sid]
    active = set(c.loc[(c.start_date <= key) & (c.end_date >= key) & (c[weekday] == 1),
                       "service_id"])
    exc = cdates[sid][cdates[sid]["date"] == key]
    active = ((active | set(exc.loc[exc.exception_type == 1, "service_id"]))
              - set(exc.loc[exc.exception_type == 2, "service_id"]))
    sr = service_route[sid]
    day = (sr[sr.service_id.isin(active)]
           .groupby(["route_id", "route_short_name", "route_type"], as_index=False)[
               ["trips", "miles"]].sum())
    frames.append(day.assign(date=d, snapshot=sid, basis="published"))

actual = pd.concat(frames, ignore_index=True)
assert set(actual.date) == set(assigned), "a covered date produced no service"
print(f"{actual.date.nunique()} dates, {actual.miles.sum():,.0f} published-schedule miles")

Projecting the rest of the year

UTA had not published a schedule past the end of the latest feed when this was run. Remaining dates are projected: each copies the most recent published day with the same weekday (Dec 25 uses the Sunday pattern, matching UTA’s holiday service), excluding Thanksgiving. They are flagged basis = "projected" throughout and replaced by real data automatically once newer snapshots are archived (delete _data/remote/mdb-170_datasets.json to refresh the listing).

Show the code 
have = sorted(set(actual.date))
rows = []
d = max(have) + timedelta(days=1)
while d <= date(YEAR, 12, 31):
    wd = 6 if (d.month, d.day) == (12, 25) else d.weekday()
    ref = max(x for x in have if x.weekday() == wd and x not in PROJECTION_EXCLUDE)
    rows.append(actual[actual.date == ref].assign(date=d, basis="projected", snapshot=assigned[ref]))
    d += timedelta(days=1)

daily = pd.concat([actual, *rows], ignore_index=True)
daily["date"] = pd.to_datetime(daily["date"])
assert daily.date.nunique() == 365

Limitations

  • Scheduled, not operated. Based on published GTFS: no deadhead, missed trips, detours, or unscheduled extra service.
  • Microtransit / on-demand miles are only as good as what UTA publishes in GTFS; on-demand (demand-response) service has no scheduled trips and is absent from the 2026 feeds, so it is excluded entirely.
  • Mode lookup is by route short name as supplied; routes added or renumbered since are flagged under Unmapped.
  • Shape-based distance is straight-line between shape vertices, so slightly shorter than odometer miles on very sparse shapes.
  • Projected days assume the last published schedule continues; a December service change would shift them.
